# Animation Lab — MVP plan: Lens & Framing Lab

## Context

Animation Lab is an interactive school for animated filmmaking. The MVP is one lab, **Lens & Framing**: a stylized animated 3D set with two original characters performing a 6 s loop, filmed by a virtual cinema camera. Users change focal length and camera distance and watch the **actual animated shot** change in a large, crisp director's monitor, in two modes: **Fixed camera** (only the field of view changes) and **Match subject framing** (the camera dollies to keep the subject the same size, so perspective visibly changes). The long-term motive is to transfer this understanding into how TrueStudio prompts AI video models (Seedance 2.5), so the lab also emits shot language.

Repo: `/Users/gg/w/animation-lab`. The user scaffolded Next.js 16.4.3 (TypeScript, Tailwind 4 via `@tailwindcss/turbopack`, ESLint 9, `src/app`, `@/*` alias, git initialized with the template commit, `FAL_API_KEY=` in `.env.local`/`.env.example`). Everything below *adjusts* that scaffold. All work is written to the working tree only — never `git add`/`commit`/`vercel` unless the user asks.

Decisions made with the user (2026-11-01):
1. **Theme:** dark cinematic stage in the spirit of Plane of Focus (graphite/navy stage, warm practicals, cyan frustum, amber selection, dark glass panels). All colors are tokens.
2. **Layout:** 3D stage full-bleed + large director's-monitor overlay (~40 % width, 16:9) showing the live shot; `V` swaps which is primary; `⇧F` makes the shot fullscreen. Filmstrip of lens presets at the bottom; controls panel top-right; readout chips + caption + concept panel top-left.
3. **Assets:** procedural stylized characters with deterministic keyframe animation. Meshy via fal.ai only for 1–2 static set pieces, ≤ $10 total, only if the procedural versions look weak. Never at runtime.
4. **Shot-language output:** a one-line prompt phrase in the UI and `prompt.phrase` in the Copy Shot Settings JSON.
5. **References:** Plane of Focus (live site and the local mirror at `~/w/plane-of-focus`) for look, feel and interaction *ideas*; its source is all-rights-reserved, so no markup, CSS, fonts (Outfit/DM Mono), layout or copy are copied. Anatomy (MIT) informs only the technical-view restraint. The user's emphasis: *show what the animation output looks like at our camera/lens settings* — the live monitor is the hero deliverable.

## Reference analysis

**Plane of Focus** (observed in Chrome and read in the local mirror `~/w/plane-of-focus/pretty/script-8-module.js`; vanilla three.js r183, one canvas, HTML glass overlays). Idea-level techniques worth borrowing:
- A "photo" camera renders what the lens sees into a render target; **three.js layers** decide what the photo camera sees versus what only the observer sees; lights `enableAll`.
- Shadow maps are updated manually once per frame (`shadowMap.autoUpdate=false; needsUpdate=true`) before the first render of the frame.
- The five filmstrip thumbnails live in one **atlas render target**, re-rendered only on a dirty flag, when the parameter moved > 4 % and ≥ 0.12 s elapsed, or every 3 s.
- **Pixel-budget DPR**: `clamp(min(devicePixelRatio, 1.5, sqrt(2.5e6 / (w·h))), 1, 1.5)`, then an fps-probing ladder that steps DPR by 0.25 and only afterwards drops features.
- One **hit-target registry** (`register(mesh, kind, data)`) and one raycast per pointer move drive cursor, tooltip verb and click dispatch per kind; pointer capture on down; drags map pointer deltas into the control's own space.
- **Cinematic camera "beats"**: a data list of shots `{ target, yaw, pitch, dist, drift, hold, beats: [[t, action], …] }` with a tiny scheduler; any input cancels the mode.
- Exponential damping with per-control rates; focus damped in diopter space; overlay labels projected after post-processing; a `ui-off` class for clean captures; a CSS vignette layer over the canvas keeps the text column legible.
- Dev hooks `__step(ts)`, `__loop(false)`, `__capture()`, `__photo()` make deterministic screenshots trivial.
- UI vocabulary (own values in our tokens): small-caps mono chip labels + mono values, one primary chip in the accent; a caption whose key words are color-coded; segmented pills with an inverted light "on"; a slider whose fill visualizes a derived quantity; mono tooltips; a top-center toast for keyboard actions; help modal with small-caps sections, a KEYS legend and an assumptions footnote; responsive collapse to a bottom sheet under 900 px.

**Anatomy skill** (MIT): one crafted machine from many purposeful parts; one lit accent; ruler strips with ticks instead of a blueprint grid; measurements as wires between terminal dots; calm time-based motion (dt clamped to 1/30); idle tour after ~1.4 s, resumes 3.6 s after input; reduced-motion jumps to targets; `aria-valuetext` written only on state changes.

**Ciechanowski "Cameras and Lenses":** one color per variable everywhere; scene + result side by side; one consistent test scene; inline "show me" links that tween to a teaching state. Pinhole-exact math (three.js, Blender and Unreal all render ideal pinholes, so exports match).

## Architecture

### Rendering: one Canvas, one scene, orchestrated passes
- `<Canvas frameloop="demand" dpr={quality.dpr} shadows={{ type: PCFShadowMap }} gl={{ antialias: true, powerPreference: 'high-performance' }} camera={{ manual: true, fov: 45, near: 0.1, far: 120 }} eventSource={labRootRef} onCreated={state => { state.setEvents({ compute: computePointer }); state.gl.shadowMap.autoUpdate = false; installContextLoss(state) }}>`, mounted client-only via `next/dynamic({ ssr: false })` inside a `'use client'` shell. No `events` prop and **no `eventPrefix`** (R3F would overwrite a custom `compute` when `eventPrefix` is set). `antialias: true` is required: the direct shot pass (the hero image), the PiP stage pass and the saved-shot crops get their anti-aliasing from the canvas context; the composer has its own MSAA.
- **FrameOrchestrator** = the single `useFrame(fn, 1)` (positive priority disables R3F auto-render). Per frame: (1) `clock.tick()` once → `frameT`; `dt = clamp(delta, 0, 1/30)`; (2) run registered updaters in `ORDER` (POSE 0 → PRESENTATION 10 → FILM_CAMERA 20 → TECH 30 → MEASURE 40) with `FrameCtx { t, dt, frameId, playing, reducedMotion, quality, rects }`; (3) `gl.shadowMap.needsUpdate = true` once; (4) **stage pass**: observer camera (`manual`, aspect = stage rect) rendered through a directly driven `postprocessing` `EffectComposer` (`RenderPass` → optional `N8AOPostPass` as its own pass → `EffectPass[Bloom, Vignette, ToneMapping ACES_FILMIC]`, HalfFloat, MSAA 2–4; M5) when the stage is primary, direct render into its scissored rect when it is the PiP; (5) **shot pass**: film `PerspectiveCamera` (`filmGauge 36`, `aspect 16/9`, `setFocalLength(f)`, layers {0}) with `setRenderTarget(null)` **then** `setViewport/setScissor/setScissorTest(true)` into the monitor window's rectangle; `scene.background` is a Color so three force-clears the region (`autoClear` is false after composer creation — assert the Color background in dev); skip any pass whose rect is < 2 px; (6) **thumbnails** (M5): ≤ 1 lens-preset render per frame into 6 × `WebGLRenderTarget(256×144, HalfFloat, samples 4)` (three resolves MSAA targets automatically at the end of `render()`), all dirty ones when paused, dirty on any camera/mode/target/time change, blitted with a tone-mapped fullscreen-triangle material (`depthTest: false, depthWrite: false, toneMapped: true`, `#include <tonemapping_fragment>` + `<colorspace_fragment>`) into the filmstrip's transparent DOM windows; (7) restore viewport, `setScissorTest(false)`, push a `FrameRecord { frameId, t, dtMs, passes, stageRect, shotRect, calls }` + DevStats phase timings (tick/updaters/shadow/stage/shot/thumbs) into ring buffers, and `invalidate()` while `playing || !presentation.settled || controls.active || thumbnails.dirty || layoutTransitioning`.
- **viewports registry** (`renderer/runtime/viewports.ts`): `setCanvas(el)`, `register(id: 'stage'|'shot'|\`thumb:${n}\`, el)` measures synchronously with `getBoundingClientRect` at register (ResizeObserver notifications arrive after the rAF callbacks of the same frame, so the first frame must not depend on them), then ResizeObserver + window resize; `get(id) → { el, css: { left, top, width, height }, gl: { x, y, w, h } /* y flipped, CSS px */, version }`, `measureAll()`, `subscribe(cb)`; `layoutTransitioning` lives here (set by `ui.setPrimaryView`, cleared on the monitor's `transitionend` or after 300 ms; `measureAll()` every frame while set). `LabLayout` renders the stage and shot slot divs **before** `<StageCanvas>` in the same commit so callback refs populate the registry before R3F's first frame.
- **Layers:** `LAYER_WORLD = 0`, `LAYER_TECH = 1`. Observer camera enables both; film camera sees only 0. A `<TechLayer>` group traverses children on mount to set layer 1 and `castShadow=false` (frustum, camera rig, rail, rulers, grid, target indicator, pills, studio dressing). Lights stay on layer 0.
- **Why not drei `<View>` or two canvases:** View portals children into a per-View scene, so the world would exist twice (double shadows, divergence risk, no shared thumbnails); two canvases cannot share GPU resources. One scene gives "same world, same time" by identity.
- **Pointer events:** `computePointer` maps clientX/Y through the current stage slot rect with the observer camera and, when the event target is not inside the stage slot, returns without calling `setFromCamera` (nothing is hit). The monitor handles its own click-to-target with a Raycaster on the film camera. R3F puts `pointer-events: none` on its wrapper when `eventSource` is set, so events come from the DOM slots under the lab root.
- **Observer camera:** drei `<CameraControls impl={ClampedCameraControls} makeDefault domElement={stageSlot} minPolarAngle=0.12 maxPolarAngle=π/2−0.04 minDistance=1.2 maxDistance=28 smoothTime=0.18 draggingSmoothTime=0.06 dollyToCursor regress>` where `class ClampedCameraControls extends CameraControlsImpl { update(delta) { return super.update(Math.min(Math.max(delta, 0), 1/30)) } }` (drei's own `useFrame` keeps calling `update`; demand mode never stops R3F's clock, so without the clamp a transition started from idle snaps). `setBoundary(descriptor.observer.boundary)`. Presets are one-shot `setLookAt(..., true)` transitions started on the frame after an `invalidate()`; the observer never follows the film camera afterwards. Dolly-drag on the camera body sets `controls.enabled = false` for the drag (camera-controls cancels its own gesture). Fallback if `impl` typing fights: the raw class via `<primitive>` with `camera-controls@^3.1.0` as a direct dependency.
- **Monitor overlay:** the shot window is a transparent DOM element with `aspect-ratio: 16/9`; bezel, thirds/safe-area SVG guides, readout strip and prompt line are DOM on top. Frames/bezels around a live window are **sibling rings (mask/clip-path), never ancestors with `backdrop-filter`**. drei `<Html>` pills use `calculatePosition` through the current stage rect (`transform={false}`) and live in a stage HTML layer with a `clip-path` hole under the monitor. Swap primary = flip `data-primary` on the lab root (CSS 240 ms unless `data-nomotion`); `⇧F` sets `data-fullscreen-shot="1"` (stage pass skipped). Optional flourish (COULD): the shot texture on a small in-world monitor on the rig.
- **Tone-mapping parity:** three applies tone mapping and output encoding only when rendering to the canvas; a `RenderPass` into any render target is linear. The parity-exact configuration is HalfFloat composer buffers + `ToneMappingEffect(ACES_FILMIC)` with `gl.toneMapping = ACESFilmicToneMapping`, exposure 1.0, sRGB output; the parity test samples a neutral card away from bloom/vignette/AO. Do not opt into r187's `outputBufferType: HalfFloatType`. Accent lines use an HDR colour with default `toneMapped`; bloom threshold ≥ 1.0 or `SelectiveBloomEffect`.
- **Context loss:** `webglcontextlost` → overlay + pause; `restored` → `shadowMap.needsUpdate`, dirty thumbnails, `composer.setSize`, remount `<Environment key={contextEpoch}>`, `invalidate()`.
- **Unmount hygiene:** all listeners in effects with cleanup; the lab root's cleanup sets `frameloop('never')`, pauses the clock and disables controls.
- **Quality table** (`renderer/runtime/quality.ts`, static from M1; `PerformanceMonitor` stepping on top in M5): `3: { dpr 1.5, post, msaa 4, ao, shadowMap 2048, thumbs live } · 2: { dpr 1.25, post, msaa 2, no ao, 2048, live } · 1: { dpr 1, no post, 1024, thumbs idle-only } · 0: { dpr 0.75, no post, 512, thumbs off }`. Resolution: `ui.quality` high → 3, low → 1, auto → 3 with dpr = pixel budget `clamp(min(devicePixelRatio, 1.5, sqrt(2.5e6/(w·h))), 1, 1.5)`; `?e2e=1` → 1 unless `quality=high`; `?dpr=` overrides. Shadow-map size changes dispose the old map. Performance budget (honest, measured from M1 with `DevStats` `?debug=1`): ≈ 220 draw calls per stage pass at first (72 character parts × 2 with outlines, set ≈ 35, rig ≈ 12, tech ≈ 10); targets 60 fps at 1440×900 dpr 1.5 on M1 Pro, 1440p dpr 1.25 on a base M1, ≥ 30 fps on a mid-range iGPU at 1080p dpr 1; reduction order: merge static set parts per material → one `LineSegments` for rulers/grid → outlines only on characters → one procedural `SkinnedMesh` per character. Lab route JS ≤ 500 kB gz; home ships no three (`scripts/check-home-bundle.mjs` reads `.next/app-build-manifest.json` and fails if a home chunk contains `WebGLRenderer`).

### Simulation engine (`src/engine`, pure TS + three math classes only; ESLint forbids react/drei/next/zustand imports; functions take the scene descriptor as an argument)
- `optics.ts`: `hfovDeg`, `vfovDeg`, `frameSizeAtDistance`, `heightFraction`, `distanceForFraction`, `focalForFraction`. Gate 36 × 20.25 mm. Table: 18 → 90.00°/58.72°, 24 → 73.74°/45.75°, 35 → 54.43°/32.27°, 50 → 39.60°/22.90°, 85 → 23.91°/13.59°, 135 → 15.19°/8.58° (h/v).
- `projection.ts`: projection/view matrices identical to three's `PerspectiveCamera` (tested element-wise), `projectPoint` → NDC, `frustumCornersAtDistance`, `frustumWire`.
- `rig.ts`: `poseFromRig` / `rigFromPose` (rail ↔ position; yaw/pitch → quaternion `YXZ`, zero roll); **`aimForNdc(cameraPos, anchorWorld, ndc, focalMm) → { yawDeg, pitchDeg }` as the exact zero-roll solve** `R_y(ψ)·R_x(θ)·c = w` with `c = normalize(x·tan(h/2), y·tan(v/2), −1)` (θ from the acos form, smaller |θ| branch; ψ from the xz components) — not an additive yaw/pitch composition (that misses by ~2 % of the frame); tests pin anchor NDC preserved within 1e-9 at NDC (±0.63, ±0.96) for f ∈ {18, 135} and `poseFromRig({ yawDeg: 90 })` forward = (+1, 0, 0).
- `matchFraming.ts`: `subjectMetric(pose, intrinsics, target)` = projected height fraction of the target's **framing box** (Both: `max(w, h)/2` of the NDC bounding box of the eight projected corners of the union); `solveMatchedFraming` evaluates `metric(railS) := subjectMetric(pose(railS, aimForNdc(…)))` with the re-aim folded in, seeds with the closed form `d1 = d0·f1/f0` (exact for the level centred primary) and refines with **bracketed root finding** (regula falsi/bisection, tol 1e-4, ≤ 40 iterations) — valid because the metric is strictly monotonic in railS for all targets and presets (asserted by tests); feasibility ⇔ `metric(sMax) ≥ ref ≥ metric(sMin)`; otherwise clamp and report `clamped`. Reachability from the default capture: all presets for Bram; **Pip ≈ 25–107 mm; Both ≈ 19–120 mm** — outside the band the solve clamps with the hint "Rail end — Pip can't be matched below ~25 mm from here", the filmstrip tiles and slider bands outside the band are hatched, and the chip reports the achieved metric. Framing boxes: Bram = head & shoulders (y 1.08–1.86, half-width 0.30, anchor 1.47); Pip = full height (0–1.12, half-width 0.26, anchor 0.56, at his final mark); Both = union of those two boxes, `anchors.both` = centre of the union (0.185, 0.93, −3.85). TargetPicker disables Both **only in Match mode** when a dry-run solve at the current focal with the current metric clamps; reason "Not feasible on this rail at {f} mm — try ≤ {fMax} mm".
- `bounds.ts`: rail `[sMin −5.4, sMax +2.4]`, no-go sphere 0.45 m; `bounds.test` asserts min depth > 0.25 m for every anchor over the whole rail.
- `measure.ts`: `Measurements { focalMm, hfovDeg, vfovDeg, targetId, targetName, distanceM (to the active anchor), distanceToPrimaryM, railS, cameraPosition, pitchDeg, elevationToTargetDeg, subjectFraction (framing box), bodyFraction (full height), frameWidthAtSubjectM, doorwayWidthFraction, backWallCoverageWidthM, bgRatioVs24 (Match only; null in Fixed), fgBgMagnification (null when the lantern is < 0.6 m away or behind the camera), faceStretch (from puppet markers depth(ear)/depth(noseTip); null when the head faces > 45° away), apparentHeightRatio, kRatio, shotSize, lensClass, angle, perspective, timeS }` — all from the actual pose/projection and the descriptor landmarks. **Copy tokens are Measurements keys with formatters** (`{focalMm}`, `{distanceM:0.00}`, `{subjectFraction:%}`, `{doorwayWidthFraction:%}`, `{apparentHeightRatio:×}`, `{bgRatioVs24:×}`, `{targetName}`), so a missing field fails typecheck.

## Resolved design questions
- Canonical camera: position on the rail + explicit yaw/pitch (not an orbit about the target anchor), so the camera stays on the rail at constant height for every target; one axis, one number for distance.
- View architecture: single canvas, one scene, orchestrated passes; `antialias: true`; composer for the stage only; no `eventPrefix`, compute installed in `onCreated`; drei `CameraControls` with a delta-clamping `impl` subclass.
- Match metric: the target's framing box (Bram head & shoulders, Pip full height, Both union bbox); capture records the current metric (no re-framing on capture); bracketed solve; feasibility bands surfaced in the UI; shot size from full-body fraction via one `classify.ts` table; angle from elevation to the target.
- Perspective class from the back wall (z −9) with 0.18/0.45 thresholds; Fixed-mode lens changes never change it.
- `cacheComponents` off; `dynamicParams = false`; lab-aware root not-found; dev routes gated; `scripts/` outside the root tsconfig.
- Thumbnails: render targets blitted in-canvas (M5); saved shots as text tiles first. Outlines are character style → visible in both views. Characters Bram (1.78 m) and Pip (1.05 m). Fonts Instrument Sans + JetBrains Mono. `FAL_API_KEY` kept. `?` help / `⇧U` hide UI. Intro/drift are COULDs.
